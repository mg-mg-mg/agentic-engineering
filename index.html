1. Owner attention is the scarcest resource

The repo contract (AGENTS.md, ~63 KB plus nested rules and task skills) makes decision rights explicit. An agent that stops to ask for a decision it could make costs more than a reversible mistake it catches and fixes.

Decision rights: agents act; the Owner approves irreversible effects
DecisionWho
Technical design, root-cause scope, refactoring, slicing, test strategy, task orderAgent decides and reports why
Defects found while working, tooling recovery, Issues, branches, worktrees, PRs, docs and rule updatesAgent acts then records
Deployment, store submission, payments, production data, external messages, spending, credentialsOwner approves asked once, with a recommendation

2. Current system: native OMP

One authorized LEADER owns delivery. Root roles define ownership, not a claim that every role is running.

Ownerproduct, priorities, irreversible approvals

Root roles

  • LEADER & DELIVERY: queue admission, integration, merge and cleanup
  • RELEASE, DISCOVERY, OPS & GROWTH, BILLING MIGRATION: specialist ownership and handoffs to LEADER
  • Capacity follows host authorization and measured memory headroom, not a fixed worker count

Author → independent review

  • One sole branch author, one task worktree; generated surfaces have one owner lane
  • Distinct read-only reviewer at fixed head/base SHAs; highest matching risk tier sets effort
  • Delta re-review returns to the original reviewer while available

Browser agent (QA / ops)

  • Live E2E: payment checkout, refund, cancel in test mode
  • 7-locale i18n/UX audits, dashboard audits
  • Files Issues to coding lanes via a repo mailbox and a local control channel of the harness

Harness history: TriAstra started on Codex and Claude Code, moved through Oh My Pi and jcode, and has now consolidated on Oh My Pi (omp). The rules live in the repository, not in a tool, so switching harnesses did not reset the process.

Worktree contract: inspect existing lanes, claims and prerequisites; fetch through the existing guard; create or reuse one task-specific lane from the integration head and record its starting SHA. Verify checkout identity, clean status and the authorized environment link. No duplicate lanes or stacked task branches; dependencies wait for main.

Trusted OMP configuration is not an enforced sandbox. Actual host permissions, authorization, single-writer ownership, owner approvals and independent review are the boundaries.

Sep 27 – Oct 8, 2026: unattended Issue pool (historical; final configuration from Oct 7)

In its final configuration from Oct 7, the retired dispatcher ran four macOS LaunchAgent workers on a 180-second tick, each claiming one unowned P1/P2 bug or maintenance Issue. Payments, Owner holds, unresolved dependencies and owned work were excluded.

An offline, minimal-read author sandbox had no secrets, credentials, network, commit or push access. A trusted dispatcher validated state, reviewed the diff, disabled candidate hooks, published the PR and verified its head. Separate read-only review at fixed SHAs and credentialless verification returned findings to the author for a new head, fresh review and checks, within a five-hour budget.

Guarded merge saved intent, pinned the squash merge, checked parent/tree and reconciled Issue/Project with evidence. The offline isolation taught least-privilege lessons; it is not today's trusted OMP permission model. Historical reference code.

Never unattended: deployments, app-store submissions, production data writes, payments, credential changes, external messages.

4. What I learned

1

Throughput is cheap; trust is expensive.The bottleneck moved from writing code to acceptance criteria and gates that make agent output trustworthy without reading every line.

2

Separate the roles.A model reviewing its own work misses the same things. A distinct read-only reviewer and proportionate independent proof matter more than repeating every check.

3

Least privilege for agents.The historical dispatcher isolated offline authors from credentials. Today's trusted OMP relies on host authorization, single-writer ownership and owner approvals, not a claimed sandbox.

4

Write the rules where agents read them.Decision rights and workflows live in versioned repo docs, so every session starts from the same contract and rules improve through PRs.

5

Find errors before runtime.Typed contracts and generated clients turn agent mistakes into build failures instead of production incidents.

6

Spend human attention on the irreversible.I approve deploys, payments, pricing, and policy. Almost everything else is delegated and audited.
