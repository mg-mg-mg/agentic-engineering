Independent review changes outcomes

In one historical case, a separate reviewer caught a privacy problem in a chart-calculation-range fix before merge. In a distinct October 2026 billing case, test-mode refund E2E showed that refunded reports continued generating; an author added regression coverage and fixed the behavior, a separate reviewer checked it, and the fix reached production.

The billing case predates standing release authority. Its original Owner approvals are history, not today's deployment rule. Requested changes, author repairs and independent delta review—not rubber-stamp approvals—are part of the delivery loop.

2. The current native system

Five long-lived OMP root roles work one canonical GitHub queue. Role ownership is not proof that all sessions are currently running.

Ownerproduct, priorities, bounded authority

Delivery and release

  • LEADER & DELIVERY: admission, coordination, cross-root integration conflicts and cleanup; may integrate any authorized PR
  • RELEASE: exact-commit readiness, ordinary releases within standing approval, and approved release/store evidence

Discovery and operations

  • DISCOVERY: audits, evidence-backed Issues and authorized direct fixes with independent exact-diff review
  • OPS & GROWTH: analytics, support preparation and content/campaign work; only exact approved external effects

Migration and bounded slices

  • BILLING MIGRATION: migration scope, handing support and release to their owning roots
  • Bounded subagents, live host limits and measured heavy-work headroom—not a permanent worker-count rule
  • One writer per branch and generated surface; authors own checks, commits, push and PRs
Canonical GitHub Issues · PRs · Project · no extra dispatcher, queue ledger or timer scheduler

Authoring roots may integrate their own independently reviewed PRs; LEADER may integrate any authorized PR and resolves cross-root conflicts.

Admission follows actual progress. Finish actionable existing PRs before ordinary new implementation, then admit eligible independent Issues. Distinguish working, waiting, idle and unknown. Silence does not terminate a writer or transfer custody. Record a blocked item's resumption condition and continue other authorized work.
Observation-only holds. Landed code, released code and observed outcomes are distinct states. Keep an observation-only Issue open with its window and due check; admit the check, not another implementation attempt.

Browser and peer messages. A browser teammate handles authorized test-mode E2E flows, locale/UX audits and read-only dashboards. Browser communication uses a file mailbox and notification relay. Coding sessions use direct addressed delivery between sessions, with recipient liveness checks and no browser relay. Messages use Request / Result / Next / Needs reply sections and carry no authority; durable decisions and evidence belong on the owning Issue or PR. The two transports are different mechanisms, not evidence of an identical end-to-end benchmark.

How it evolved — October 2026. Earlier work used Codex and Claude Code, then OMP and jcode; the current coding host is OMP. The timer-driven pool and privileged dispatcher were retired. Separate verifier replay and per-deploy approval are historical. The public kit is a historical/synthetic reference with reusable lease, guards and navigation evaluation mechanisms—not the current workflow or a demonstrated OMP adapter. Synthetic tests do not establish live sandbox containment.

3. Gates that make speed safe

Targeted proofSelect regressions and actual changed-path smoke by risk and affected consumers; self-review and rebase as needed.
Independent fixed-pair reviewA distinct read-only session reviews exact head/base commits and the predicted merge tree, including newly tracked files and integration interactions.
Full gate once, lastResolve findings first. Run the required broad gate on the final reviewed head; no extra verifier merely to repeat another lane's suite.
Qualified evidence reuseInspect original logs and prove relevant inputs equivalent. Retain the original tested commit and disclose warm-binary reuse. Changed inputs or uncertainty require affected checks again.
Pinned integrationComplete admission before a fail-closed main lease; pin the reviewed head and read back the merge parent and predicted tree. Releases use a separate lock and pinned checkout.
A changed head/base needs independent fresh or qualified delta review. Required independently observed changed-path proof still matters. Missing, failed or interrupted evidence blocks admission. Record executed checks, reused evidence and remaining gaps separately; no unmeasured speedup is implied.
Before runtime. Typed contracts, generated-client freshness, owning tests and actual-surface visual proof cover relevant risks. Inventory which gate executes each test and its explicit exclusions. Native tool locks and measured headroom replace retired Cargo-slot caps.
AI-managed locale quality. All seven locales, including Korean, start from locale-neutral meaning and require independent exact-text-hash PASS + LLM_CRITIQUED. Sensitive copy also needs domain review; pricing, legal and policy facts retain their owners.

Confirm callers and impact in source, rather than trusting an index.
